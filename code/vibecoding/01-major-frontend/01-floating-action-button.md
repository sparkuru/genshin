# Floating Action Button / Speed Dial 悬浮快捷菜单设计

## 一、项目目标与设计定位

实现一个具备高品质视觉表现、流畅交互体验和完整响应式适配能力的多端可用 **Floating Action Button（FAB）/ Speed Dial 悬浮快捷操作菜单**。

整体交互理念参考 Twitter（X）、Tumblr 等产品的悬浮发布按钮，但不直接复制现有设计，而是在其交互逻辑基础上进行视觉与体验创新。

**设计品质以 Awwwards、The Webby Awards、FWA 等国际数字设计奖项中的优秀获奖作品为参考标准**，追求精致、克制、现代、具有辨识度的视觉语言，以及经过充分打磨的交互细节。

最终效果应呈现出成熟商业产品的完成度，而非普通组件库的默认样式。

## 二、核心功能与交互逻辑

### 1. 悬浮按钮（FAB）

- 提供一个始终悬浮于页面内容上方的主操作按钮，作为快捷操作菜单的统一入口。
- 主按钮采用精致的圆形或经过适度设计的超椭圆造型，兼顾视觉辨识度与触控舒适性。
- 默认使用简洁、明确的操作图标，例如「+」，并允许根据业务场景进行配置。
- 点击主按钮时展开 Speed Dial 快捷操作菜单；再次点击则收起。
- 按钮应具有明确的默认、悬停、按下、展开、拖动及禁用状态。
- 按钮的层级、阴影及动态反馈应能够清晰表达其悬浮属性，但不能产生过度突兀的视觉效果。

### 2. 页面内自由拖动

- 主悬浮按钮支持在当前页面可视区域内自由拖拽，不限制于固定的右下角位置。
- 同时兼容 Touch Events、Pointer Events、鼠标及触控板操作。
- 拖动过程中按钮应实时跟随指针或手指移动，保持低延迟和稳定的视觉响应。
- 拖动范围需考虑屏幕安全区域、刘海屏、圆角屏、底部手势导航区域及虚拟键盘。
- 按钮不得被拖出可视区域，且应避免停留在无法操作的位置。
- 可提供轻量化的边缘磁吸效果，但必须保留自由定位能力，不应强制限制用户只能将按钮停靠于屏幕两侧。
- 拖动结束时允许使用符合真实物理直觉的弹性缓动，避免生硬停止。
- 明确区分「点击」与「拖动」手势，防止拖动时意外触发菜单。
- 支持记忆用户最后一次放置的位置，并在页面刷新或重新访问时恢复。
- 屏幕尺寸、方向发生变化后，应自动修正悬浮按钮位置，保证其始终可见且可操作。

### 3. Speed Dial 菜单展开与收起

- 点击主按钮后，以其当前位置为视觉原点展开多个快捷操作项。
- 支持垂直排列、扇形排列或轻量化弧形排列，可根据实际设计方案选择最合适的布局。
- 菜单展开方向应根据按钮位置和屏幕剩余空间自动调整。
- 靠近屏幕底部时优先向上展开；靠近顶部时优先向下展开；接近左右边缘时自动调整菜单的展开方向和对齐方式。
- 所有菜单项必须完整显示于可视区域内，避免内容溢出、遮挡或被裁切。
- 每个操作项包含高质量图标，并可搭配简短文字标签。
- 支持动态配置操作项的数量、图标、名称、排序和点击事件。
- 点击操作项后执行对应功能，并根据业务逻辑自动收起菜单。
- 点击菜单外部空白区域、再次点击主按钮或按下 Escape 键时，应能够自然收起菜单。
- 菜单展开期间需妥善管理页面其他交互，避免触摸冲突及误操作。

## 三、视觉设计要求

### 4. 排版与字体系统（Typography）

- 建立统一、清晰、专业的字体层级体系。
- 采用现代、简洁、具有良好屏幕可读性的字体设计。
- 文字标签在字号、字重、字距及行高方面进行精细调整，避免采用浏览器默认排版效果。
- 菜单文字应突出可读性，同时保持轻盈、克制的视觉感受。
- 图标与文字必须实现精准的光学对齐，而非仅依赖数学居中。
- 保持中英文混排、数字和不同长度菜单标签之间的排版一致性。
- 避免过度使用粗体、描边、复杂字效等影响界面精致度的设计。

### 5. 留白与空间节奏（Spacing & Rhythm）

- 建立基于统一间距尺度的布局系统，建议使用 4px / 8px 基础间距体系。
- 精确控制主按钮、菜单项、文字标签、屏幕边缘之间的距离。
- 菜单展开后应具有合理的呼吸感，避免操作项过度紧凑或松散。
- 利用留白建立明确的组件边界及视觉节奏。
- 对菜单项间距、图标容器尺寸、标签内边距、圆角和阴影扩散范围进行统一设计。
- 视觉效果应体现经过细致调整的空间比例，而不是简单叠加标准 UI 组件。

### 6. 视觉层级与组件形态（Visual Hierarchy）

- 主按钮必须成为组件内最明确的视觉焦点。
- 次级操作按钮和文字标签应形成清晰、递进的视觉层级。
- 使用尺寸、色彩、对比度、阴影、透明度及空间关系区分不同交互层级。
- 精细处理圆角曲率、边缘过渡和图标线条粗细。
- 主按钮和子菜单之间应具有一致的设计语言。
- 菜单展开后，可使用轻量级背景遮罩或局部背景模糊增强聚焦效果，但不得严重干扰页面内容。
- 控件应具有适当的悬浮感和空间深度，避免厚重、廉价的立体阴影。
- 整体视觉应追求高级感、秩序感及一致性，而非单纯依靠炫目的视觉效果吸引注意。

### 7. 色彩系统（Color System）

- 建立统一的语义化色彩体系，包括主色、辅助色、背景色、表面色、文本色、边框色及交互状态色。
- 使用具有辨识度且与整体页面协调的品牌主色。
- 合理组织色彩的明度、饱和度与对比关系，使主按钮具有充分识别度。
- 避免无意义的高饱和撞色、复杂渐变及过量发光效果。
- 如果采用渐变、半透明材质或玻璃质感，应保持克制，确保视觉效果精致而非装饰过度。
- 对所有交互状态设计明确的色彩反馈，包括按下、选中、激活及禁用。
- 同时适配浅色模式和深色模式，确保不同主题下仍具有良好的视觉一致性。
- 文字及必要图形应满足 WCAG 2.2 AA 的适用对比度要求。

## 四、动效与微交互设计

### 8. 动效系统（Motion Design）

动效必须成为交互体验的一部分，而不是独立存在的视觉装饰。

**菜单展开动效：**

- 主按钮图标通过旋转、形变或状态切换自然过渡，例如「+」平滑旋转为「×」。
- 子菜单按钮从主按钮附近依次出现，产生明确的空间关联。
- 合理组合位移、透明度、缩放等属性，形成具有层次感的入场动效。
- 使用轻微错峰（Stagger）表现多个操作项依次展开的过程。
- 动画建议以 180–320ms 为主要时间区间，并根据交互复杂度进行调整。
- 缓动曲线应自然、轻盈，可适当采用弹簧物理模型，但需控制回弹幅度。
- 避免机械化的线性运动、明显卡顿或夸张弹跳。

**菜单收起动效：**

- 与展开动画保持统一的运动语言。
- 子菜单自然回归主按钮附近，建立明确的空间连续性。
- 允许收起动画略快于展开动画，使界面操作更加利落。
- 在连续快速点击时，动画必须能够正确中断、反向或衔接，不出现闪烁和状态错乱。

**拖动动效：**

- 拖动开始时提供轻微缩放、阴影变化或浮起反馈。
- 拖动过程中保持即时跟手，不应为了追求平滑而产生明显滞后。
- 松手后采用自然的减速或轻微弹性归位效果。
- 如启用边缘磁吸，应通过连续、柔和的动画完成停靠，避免位置突变。

### 9. 微交互（Micro-interactions）

- 每一次有效操作都应具备明确、及时且一致的视觉反馈。
- 按下按钮时通过轻微缩放及阴影变化传达触觉感。
- 子菜单选中后应产生短暂、精致的状态反馈。
- 图标切换过程应自然连续，避免突然替换带来的视觉割裂。
- 菜单项文字标签可以采用轻量级的淡入与位移过渡。
- 支持在设备与浏览器允许的情况下提供可选的轻触觉反馈。
- 所有微交互需遵循统一的动效规范，不应出现风格不一致的动画。
- 避免不必要的循环动画、持续闪烁和过度吸引注意力的装饰效果。

整体动效应达到「能够感知，但不会打断操作」的效果。

## 五、响应式与多端适配

### 10. 响应式布局（Responsive Design）

- 采用 Mobile First 的设计策略，优先针对多端进行交互与视觉优化。
- 兼容常见的 iOS、Android 手机屏幕，以及平板和桌面浏览器。
- 支持不同视口宽度、高度、屏幕方向及设备像素密度。
- 主按钮视觉直径建议控制在 52–60px 区间，并根据设计系统进行调整。
- 所有可交互元素应具有不小于 44×44 CSS 像素的舒适触控区域。
- 使用 `safe-area-inset-*` 等机制正确处理设备安全区域。
- 菜单布局不能依赖固定屏幕尺寸或固定坐标。
- 当展开空间不足时，应动态压缩合理间距、调整排列方向或切换为更适合当前视口的菜单形态。
- 在页面滚动、容器尺寸变化、屏幕旋转及软键盘弹出时，悬浮按钮与菜单均应保持布局稳定。
- 避免遮挡重要内容、页面主要导航和系统级操作区域。

### 11. 可访问性与操作友好性（Accessibility）

- 为所有按钮配置明确的语义标签及辅助技术可识别的操作名称。
- 正确管理菜单的展开状态、焦点顺序与键盘操作。
- 支持键盘焦点显示、Enter / Space 激活及 Escape 关闭。
- 菜单关闭后合理恢复焦点。
- 尊重系统的 `prefers-reduced-motion` 设置，在用户要求减少动画时提供简化动效。
- 不得仅依赖颜色表达重要状态。
- 点击目标需要拥有足够大的操作区域，并避免相邻项目过近造成误触。
- 拖动功能不能成为使用快捷操作的唯一前提，必须始终支持常规点击操作。

## 六、工程实现与性能质量

### 12. 性能与流畅度（Performance）

- 以主流移动设备上稳定、流畅的 60fps 动画表现为优化目标。
- 优先使用 `transform` 和 `opacity` 实现高频动画，减少不必要的布局重排与重绘。
- 拖动过程中避免频繁触发 React / Vue 等框架的全量组件更新。
- 合理利用 Pointer Events、`requestAnimationFrame` 或相应动画机制处理手势和位置变化。
- 避免过量使用大面积实时模糊、复杂阴影和昂贵的视觉滤镜。
- 使用 GPU 友好的动画策略，控制合成层数量和内存消耗。
- 页面滚动与按钮拖动之间应具有正确的手势识别机制，不得产生滚动卡死或手势抢占。
- 组件挂载、卸载和页面切换时，正确管理事件监听器、动画状态和资源释放。

### 13. 组件化与可维护性

- 将 FAB 主按钮、Speed Dial 菜单、操作项、拖动逻辑和动画配置进行合理模块化。
- 提供清晰的组件 API，支持配置操作项、图标、标签、初始位置、主题及事件回调。
- 优先使用统一的 Design Tokens 管理颜色、尺寸、间距、圆角、阴影和动画参数。
- 不应将样式、业务逻辑与拖动交互深度耦合。
- 采用可靠的状态管理机制，避免展开、收起、拖动及点击事件之间的竞态问题。
- 在不增加明显复杂度的前提下，尽可能减少不必要的第三方依赖。
- 代码结构应清晰、可复用、可扩展，并具备实际产品环境中的稳定性。

## 七、细节处理与异常场景

必须考虑并妥善处理以下情况：

1. 按钮靠近屏幕四角时，菜单能够智能选择展开方向。
2. 子菜单数量变化时，布局可以自动适配。
3. 拖动过程中不会意外触发菜单操作。
4. 菜单展开状态下开始拖动主按钮时，能够正确处理展开状态，避免菜单残留。
5. 快速连续点击不会产生动画叠加、闪烁或状态不同步。
6. 页面滚动时，悬浮按钮不会发生非预期位置偏移。
7. 虚拟键盘弹出和关闭时，按钮不会被挤出可视区域。
8. 设备旋转或视口尺寸改变时，菜单不会被裁切。
9. 页面存在弹窗、抽屉、导航栏等高层级组件时，能够合理处理悬浮按钮的层级关系。
10. 操作项文本较长、存在多语言或动态数据时，仍能保持布局稳定。
11. 用户开启减少动态效果模式后，所有功能仍可正常使用。
12. 浏览器不支持特定视觉效果或触觉反馈时，提供合理的降级体验。

## 八、最终视觉与体验标准

最终作品应以高质量数字产品的设计完成度作为验收基准，重点体现以下特征：

**视觉方面：** 具备成熟且统一的设计语言；字体、图标、色彩、阴影、边框、圆角及留白之间具有高度一致性。能够呈现 Awwwards、Webby Awards、FWA 优秀数字体验作品中常见的精致细节与视觉秩序，但不依赖堆砌视觉特效。

**交互方面：** 操作直观、反馈明确、过渡自然。拖动、点击、展开、选择与关闭构成完整且连续的交互体验，没有突兀的状态切换。

**动效方面：** 具有明确的运动逻辑、自然的物理质感和精确的时间节奏。每段动画都应服务于用户的空间感知、操作确认或状态理解。

**响应式方面：** 不同屏幕尺寸和设备环境下均具有合理的布局表现，而非仅在单一演示尺寸下视觉完美。

**工程方面：** 保持高性能、低延迟、可访问、可维护，不因复杂动效牺牲基本操作效率。

## 九、最终交付要求

交付内容不应仅是一个能够展开和收起的基础 FAB 组件，而应是一个 **具备完整设计系统、精细动效、高度可用性和实际产品部署品质的多端悬浮快捷操作组件**。

最终成果需要同时满足：

- 功能完整且交互稳定。
- 可以在页面可视区域内自由拖动。
- 菜单能够根据按钮位置智能适配展开方向。
- 视觉设计具有明确的原创性和高级感。
- 排版、留白、色彩与视觉层级经过系统性设计。
- 每一处动效和微交互都具有合理的行为逻辑。
- 在多端具备优秀的响应速度与触控体验。
- 兼容主流设备，并考虑可访问性和异常场景。
- 具有成熟商业产品的细节完整度。

**核心设计原则：功能优先、视觉克制、交互自然、动效精致、细节严谨。追求获奖级数字体验作品的完成度，而不是单纯增加动画和装饰。**
