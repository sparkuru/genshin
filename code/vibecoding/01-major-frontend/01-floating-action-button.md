# 多端 Floating Action Button / Recursive Speed Dial 悬浮快捷菜单完整设计

## 一、项目目标与设计定位

设计并实现一个面向现代 Web 应用的高品质多端 **Floating Action Button（FAB）/ Recursive Speed Dial 悬浮快捷操作菜单系统**。

整体交互理念参考 Twitter（X）、Tumblr 等产品的悬浮快捷操作按钮，视觉风格以提供的参考图片为核心依据，在此基础上进行系统化设计与精细化完善。

组件必须同时具备以下核心能力：

1. **自由拖动：** 主悬浮按钮可在页面可视区域内任意拖动、定位和停留。
2. **快捷展开：** 点击主按钮后，以按钮为视觉锚点展开快捷操作菜单。
3. **递归子菜单：** 任意层级的菜单项均可继续展开下一层菜单，支持树状数据结构与递归渲染。
4. **智能布局：** 根据按钮位置、屏幕边界、菜单数量及层级深度动态调整展开方向与布局。
5. **精致视觉：** 采用参考图中的圆形图标按钮、胶囊形文字标签、纤细描边、低饱和色彩和柔和阴影。
6. **高级动效：** 具备自然、连续、富有空间逻辑的展开、收起、切换、拖动与返回动画。
7. **完整适配：** 在多端、平板和桌面浏览器中保持一致、可靠的交互体验。

设计品质以 **Awwwards、The Webby Awards、FWA** 等国际数字设计奖项中的优秀获奖作品作为参考标准。

这里的获奖级品质不是指大量动画、复杂渐变或夸张装饰，而是强调：

- 高度统一的视觉设计语言
- 精准的排版、比例和留白
- 清晰且合理的视觉层级
- 自然、流畅、有目的性的动效
- 细腻、及时、一致的微交互
- 具有空间逻辑的递归菜单体验
- 完整的响应式与无障碍支持
- 可用于实际生产环境的代码质量

**最终成果应达到成熟商业产品的视觉与交互完成度，避免呈现普通组件库 Demo、默认 Material Design FAB 或简单的弹出式按钮列表效果。**

## 二、核心视觉风格与设计语言

### 2.1 设计风格定位

以参考图片中的悬浮快捷菜单为主要视觉方向。

整体采用 **Minimalism + Soft UI + Refined Outlined Controls** 的设计语言。

视觉气质应体现：

- 极简、轻盈、安静、理性
- 精致、克制、现代
- 清晰的几何结构
- 低饱和、协调的色彩
- 轻量化的悬浮层次
- 细腻但不喧宾夺主的视觉反馈
- 具有设计系统一致性的控件细节

整体应更接近高品质编辑器、创意工具、设计工作台中的悬浮工具组件，而非传统移动应用中厚重、强烈、高饱和的快捷按钮。

### 2.2 参考图片的核心视觉特征

必须重点保留以下视觉特征：

**1. 圆形图标按钮（Circular Icon Button）**

- 采用完整、规整的圆形轮廓。
- 具有纤细、清晰、低饱和的描边。
- 使用极浅的表面底色。
- 图标严格居中，并进行必要的光学对齐。
- 通过轻微阴影建立悬浮感。
- 默认状态保持低调，交互状态通过描边、底色及图标颜色变化进行反馈。

**2. 胶囊形文字按钮（Pill Label）**

- 文字标签采用两端完全圆润的胶囊造型。
- 根据文字长度动态调整宽度。
- 内部留白充分，具有舒适的横向呼吸感。
- 与圆形图标按钮保持一致的边框、底色及阴影语言。
- 字重适中，避免过粗。
- 文本与图标在垂直方向上保持视觉居中。

**3. 标签 + 图标组合**

参考图片中的每一行菜单项由两个视觉部分组成：

- 左侧：胶囊形文字标签
- 右侧：圆形图标按钮

二者需要保持：

- 稳定的水平间距
- 一致的高度比例
- 协调的视觉重量
- 统一的交互反馈
- 明确的功能关联

默认将文字标签和图标视为同一个逻辑操作项。两部分均可触发相同操作，但不应通过嵌套两个原生按钮实现，以免造成重复焦点或无效 HTML 结构。

允许根据业务需求配置仅图标、仅文本或组合模式。

**4. 激活状态**

参考图片中的选中项通过青绿色进行表达。

激活态应优先采用：

- 更明确的强调色描边
- 淡青绿或灰绿色背景
- 与边框协调的图标颜色
- 轻微的阴影变化
- 必要时适度增强边框视觉重量

避免使用大面积纯色填充或过度鲜艳的强调色。

**5. 主 FAB 按钮**

参考图中的主按钮位于菜单下方，整体尺寸略大于普通操作按钮。

默认采用：

- 大圆形轮廓
- 浅色表面
- 纤细描边
- 柔和阴影
- 简洁的中心图标

菜单展开时，主按钮图标由「+」自然过渡为「×」，用于关闭整个菜单。

必须保留清晰的主次关系：主 FAB 是整个系统的入口与视觉锚点，而菜单项是依附于主 FAB 的次级操作控件。

### 2.3 色彩系统（Color System）

整体采用低饱和、精细分层的色彩方案。

推荐设计方向：

| 色彩角色 | 建议视觉方向 |
|---|---|
| 页面背景 | 雾白、浅灰、冷灰绿色 |
| 控件表面 | 柔和白色、极浅灰白 |
| 默认边框 | 灰蓝、冷灰紫、低饱和蓝灰 |
| 主要文字 | 深灰蓝、墨色 |
| 默认图标 | 深蓝灰 |
| 激活边框 | 墨绿、青绿 |
| 激活背景 | 极浅青绿 |
| 激活图标 | 深青绿 |
| 阴影 | 低透明度中性色 |

以上为配色方向，不要求机械使用某组固定色值。

具体配色应根据整体页面主题进行统一校准，并通过 Design Tokens 集中管理。

必须支持：

- Light Mode
- Dark Mode
- System Theme

暗色模式不能简单反转浅色模式的颜色，而应重新调整背景明度、边框对比度、文字亮度及阴影策略，保证视觉层次依然自然。

### 2.4 描边、圆角与阴影

**描边：**

- 优先使用约 1px 的精细描边。
- 激活态可以适度加深或加粗。
- 描边必须在不同设备像素密度下保持稳定。
- 不使用明显厚重的外轮廓。

**圆角：**

- 圆形按钮使用完整圆形。
- 标签使用 Pill / Capsule 造型。
- 特殊面板可使用适度连续曲率的圆角。
- 避免在同一系统内混用缺乏逻辑的圆角规格。

**阴影：**

- 默认状态使用低透明度柔和阴影。
- 激活或拖动时适当提升阴影强度。
- 阴影应表达控件与页面的空间距离。
- 禁止使用夸张的大面积发光、厚重投影及明显浮雕效果。

### 2.5 排版与字体系统（Typography）

- 使用现代、简洁、可读性优秀的无衬线字体。
- 中文优先考虑系统字体及稳定的中文字体回退方案。
- 建立统一的字号、字重、行高和字符间距体系。
- 标签文案应简洁明确，尽量避免长句。
- 中文、英文和数字混排时必须保持自然的字体比例。
- 文字标签不得因为宽度变化破坏整体布局。
- 通过光学对齐处理图标与文字之间的微小视觉偏差。

参考图的文字大小、描边力度与控件尺寸之间具有较好的视觉平衡，开发时应保留这一比例关系，而不是简单套用浏览器默认字号。

### 2.6 留白与空间节奏（Spacing & Rhythm）

建立统一的 4px / 8px 基础间距体系。

精确控制：

- 胶囊标签的左右内边距
- 胶囊标签与图标按钮的水平间距
- 菜单项之间的垂直间距
- 主 FAB 与菜单列表的距离
- 不同递归层级之间的空间关系
- 菜单与视口边界之间的安全留白

菜单展开后的整体节奏应具有清晰的秩序感。

避免按钮挤压、间距不均、文字标签忽长忽短导致视觉重心混乱等问题。

建议对不同菜单项采用统一的图标列对齐机制，使文字标签可以根据内容向外延伸，而图标按钮保持稳定的视觉轴线。

## 三、主悬浮按钮（Floating Action Button）

### 3.1 基础功能

主 FAB 是整个菜单系统的唯一顶层入口。

必须具备以下功能：

- 默认悬浮于页面可视区域。
- 支持单击或轻触展开菜单。
- 菜单展开后，点击主按钮关闭整个菜单树。
- 支持任意位置拖动。
- 允许配置初始位置。
- 允许配置按钮图标、大小、颜色与状态。
- 支持在页面刷新后恢复最近位置。
- 支持跟随主题变化。
- 支持外部程序控制展开与关闭。

### 3.2 主按钮状态

至少支持：

1. Idle：默认静止
2. Hover：悬停
3. Pressed：按下
4. Dragging：拖动
5. Expanded：菜单展开
6. Collapsing：菜单收起
7. Disabled：禁用

所有状态应具备清晰的视觉反馈，并使用统一的动效语言。

### 3.3 主按钮尺寸

建议初始设计参数：

- 主 FAB 直径：56–64px
- 普通图标按钮直径：44–52px
- 图标尺寸：18–24px
- 触控目标：不小于 44×44 CSS px

这些参数应通过 Design Tokens 配置，而不是分散硬编码。

最终尺寸需要结合参考图的视觉比例进行精细调整。

## 四、页面内自由拖动（Free Dragging）

### 4.1 自由定位

主 FAB 必须能够在页面可视区域内自由拖动。

- 不限制在左侧、右侧或底部。
- 不强制吸附屏幕边缘。
- 支持用户停留在任意有效坐标。
- 可选提供轻量边缘磁吸，但默认不能影响自由定位。
- 拖动后必须保留当前位置。

组件的拖动能力不能依赖父级容器的固定布局。

### 4.2 手势识别

优先使用 Pointer Events 实现统一的鼠标、触摸和触控笔输入处理。

必须正确区分：

- 点击
- 长按
- 拖动
- 页面滚动

通过合理的位移阈值判断拖动意图。

推荐使用约 5–8 CSS px 的位移阈值作为初始调校范围，并根据设备触控特点优化。

一旦确认进入拖动状态，不得同时触发点击展开事件。

拖动过程中应保持即时跟手，避免明显延迟。

### 4.3 拖动反馈

拖动开始时：

- 按钮轻微放大或产生浮起效果。
- 阴影略微增强。
- 描边可以出现细微变化。

拖动过程中：

- 按钮实时跟随输入位置。
- 避免突然跳跃。
- 不使用导致明显跟手延迟的弹性追随动画。

拖动结束时：

- 平滑恢复默认比例。
- 阴影恢复正常。
- 保存最终位置。
- 如启用边缘磁吸，使用短促、自然的弹性动画完成停靠。

### 4.4 拖动边界

必须考虑：

- 当前视口尺寸
- 浏览器可视区域变化
- 刘海屏与圆角屏
- 底部手势操作区域
- 虚拟键盘
- 屏幕方向变化
- 浏览器缩放
- 容器滚动与页面滚动

使用 `safe-area-inset-*`、Visual Viewport 相关能力及实时测量机制处理实际可用空间。

按钮不得被拖出有效可视区域。

### 4.5 位置记忆

支持通过本地持久化记录用户最后一次拖动位置。

建议：

- 支持 localStorage 或外部存储适配器。
- 使用可适应视口变化的相对位置或归一化坐标。
- 恢复位置时进行边界校验。
- 当屏幕尺寸变化时自动修正位置。
- 支持通过配置关闭位置记忆。
- 支持重置默认位置。

## 五、Speed Dial 一级快捷菜单

### 5.1 默认展开结构

参考图片，一级菜单默认采用 **纵向堆叠式布局**。

菜单项自 FAB 附近逐个展开。

每个菜单项优先采用：

**左侧胶囊文字标签 + 右侧圆形图标按钮**

例如：

- 深色模式
- 浅色模式
- 回到顶部
- 更多操作
- 设置

其中“深色模式”“浅色模式”可以属于同一互斥状态组，并通过激活态表达当前选项。

### 5.2 菜单展开行为

点击主 FAB 后：

1. 主 FAB 进入展开状态。
2. 主图标由「+」过渡为「×」。
3. 操作项以 FAB 为视觉原点展开。
4. 操作项依次进入可视区域。
5. 菜单进入可交互状态。

展开过程需要体现明显的空间来源关系，而非简单显示隐藏。

### 5.3 菜单收起行为

支持以下方式：

- 再次点击主 FAB。
- 点击菜单外部空白区域。
- 按下 Escape。
- 执行需要自动关闭菜单的操作。
- 外部程序调用关闭方法。

收起时，菜单项应自然向 FAB 附近回归。

### 5.4 菜单项类型

支持：

- 普通操作项
- 状态切换项
- 单选项
- 多选项
- 父级菜单项
- 分组项
- 分隔项
- 禁用项
- 异步操作项

不同类型需要具有一致的基础视觉语言，同时具备必要的语义区分。

## 六、递归式多级子菜单（Recursive Nested Speed Dial）

**这是整个组件的核心要求之一，必须作为基础架构实现，而不是后期附加功能。**

### 6.1 无限层级的数据结构能力

菜单系统必须采用树状数据结构。

任意菜单节点均可包含子节点。

支持：

- 一级菜单
- 二级子菜单
- 三级子菜单
- 更深层级的递归菜单

不应在组件逻辑中硬编码最多两级或三级。

数据结构层面应支持任意有效深度，展示层面则根据实际屏幕空间自动调整。

### 6.2 节点类型与执行规则

**叶子节点（Leaf Node）**

- 点击后执行对应操作。
- 可选择执行完成后关闭整个菜单。
- 可选择执行后保持菜单展开。
- 可展示选中、加载或禁用状态。

**父级节点（Branch Node）**

- 点击后进入下一级菜单。
- 默认不执行最终业务操作。
- 通过箭头、状态或层级提示表达可继续展开。
- 当前父级项需要有明确的激活反馈。

父级节点和叶子节点必须具有可预测的交互行为。

如需同时支持父节点执行动作与展开子菜单，应采用明确的独立交互区域或配置策略，不应让一次点击产生歧义。

### 6.3 递归渲染机制

使用统一的菜单节点结构递归生成 UI。

要求：

- 任意节点可包含 `children`。
- 子节点继续复用相同的菜单组件。
- 支持动态嵌套。
- 支持菜单树运行时更新。
- 支持节点增删、排序和禁用。
- 支持根据权限或上下文动态生成子菜单。
- 支持任意层级异步加载菜单数据。
- 支持递归节点的独立选中状态及展开状态。

递归渲染过程中不能造成重复监听、无限循环或状态污染。

### 6.4 多级菜单展开形式

采用 **智能混合式布局策略（Adaptive Recursive Layout）**。

优先考虑两种模式。

**模式 A：相邻递进展开（Cascading Expansion）**

空间足够时：

- 点击某个父级操作项。
- 子菜单从当前父项附近展开。
- 子菜单与父项形成明确的空间连接关系。
- 当前层级仍保持可见。
- 不同层级可通过距离、位置和轻微视觉差异建立上下文。

这种模式适合屏幕空间充足的场景。

**模式 B：原位层级替换（In-place Navigation）**

当屏幕空间不足时：

- 点击父级菜单项。
- 当前层菜单平滑过渡为下一层。
- 保留返回入口。
- 显示必要的当前层级标题。
- 子菜单继续沿用参考图中的胶囊标签与圆形图标风格。
- 主 FAB 保持原位置，不随层级导航发生无意义移动。

这种模式适合手机屏幕、深层递归菜单或菜单项较多的场景。

### 6.5 智能布局切换

布局不能采用固定层数判断。

应综合以下因素：

- 可用视口宽度
- 可用视口高度
- FAB 当前坐标
- 当前层菜单尺寸
- 下一层菜单尺寸
- 标签文字长度
- 菜单项数量
- 当前递归深度
- 安全区域
- 与其他已展开层级的碰撞情况

根据实时测量结果选择最合适的呈现策略。

**默认策略：**

优先尝试相邻递进展开；空间不足时自动切换为原位替换。

不能为了保留多层同时显示的效果，牺牲可读性、点击区域或视口安全。

### 6.6 多级菜单返回机制

必须区分：

**返回上一层（Back）**

- 仅关闭当前层。
- 返回父级菜单。
- 保留父级菜单状态。
- 将交互焦点恢复到对应父级项。

**关闭整个菜单（Close All）**

- 关闭全部层级。
- 收起所有子菜单。
- 主 FAB 恢复默认状态。
- 默认将层级路径重置到根节点。

不得将返回和整体关闭混为同一行为。

### 6.7 层级导航状态

采用清晰的路径式状态管理。

建议使用菜单节点 ID 路径表达当前层级，例如：

`root → appearance → theme → contrast`

根据路径可实现：

- 获取当前层级
- 返回父级
- 跳转指定层级
- 重置根菜单
- 管理父级激活状态
- 追踪当前操作来源

避免为每一层单独维护容易失去同步的布尔变量。

### 6.8 多级菜单的上下文识别

当进入较深层级时，用户必须能够明确感知当前位置。

可根据布局使用：

- 返回箭头
- 当前层级标题
- 父级名称
- 极简面包屑
- 选中父节点的视觉高亮

上下文提示必须克制，不应将轻量 Speed Dial 变成厚重的传统导航抽屉。

---

## 七、智能空间布局与碰撞检测

### 7.1 自动展开方向

菜单展开位置必须根据 FAB 的实时坐标动态计算。

例如：

- 靠近底部：优先向上。
- 靠近顶部：优先向下。
- 靠近右侧：优先向左侧延展。
- 靠近左侧：优先向右侧延展。
- 靠近角落：优先向屏幕内部展开。
- 位于中部：根据剩余空间与菜单尺寸选择合适方向。

不能只依赖固定的 `bottom`、`right` 样式控制整个菜单。

### 7.2 参考图布局优先级

默认优先保留参考图中的结构：

- 文字标签在左
- 圆形图标在右
- 菜单垂直排列
- 主 FAB 位于整个菜单的视觉终点

当空间不足时，允许整体镜像：

- 图标在左
- 文字标签在右

镜像必须保持同样的视觉精度。

### 7.3 碰撞检测

展开任意菜单层级前，应计算：

- 菜单真实尺寸
- 视口剩余空间
- 安全边距
- 与已展开菜单的重叠情况
- 与主 FAB 的位置关系

根据测量结果进行动态定位。

不得出现：

- 菜单溢出屏幕
- 标签被裁切
- 图标超出可触控区域
- 子菜单压住父菜单的必要操作项
- 递归菜单无限向同一方向溢出

### 7.4 极端空间处理

当可用空间过小时，依次采用：

1. 改变展开方向。
2. 调整菜单锚点及对齐方式。
3. 在合理范围内压缩间距。
4. 从相邻展开切换为原位替换。
5. 对操作项较多的菜单使用受控滚动区域。

不得通过无限缩小文字或按钮来强行塞入内容。

---

## 八、动效设计系统（Motion Design）

### 8.1 整体动效原则

动效应具有：

- 真实的空间来源
- 一致的运动方向
- 自然的加速度与减速度
- 明确的层级逻辑
- 克制的弹性反馈
- 稳定的状态连续性

目标是实现高品质数字产品常见的精密交互动效，而非夸张的弹跳、旋转或随机视觉特效。

### 8.2 一级菜单展开

点击 FAB 后：

- FAB 图标平滑旋转或形变。
- 菜单项由 FAB 附近逐个展开。
- 结合透明度、缩放与位移进行过渡。
- 使用轻微 Stagger 错峰增强空间层次。
- 相邻操作项保持统一节奏。

推荐初始动效参数：

| 动效类型 | 建议时长 |
|---|---|
| 按钮按下反馈 | 80–140ms |
| 主图标切换 | 180–260ms |
| 菜单展开 | 220–320ms |
| 菜单收起 | 160–240ms |
| 子菜单进入 | 200–300ms |
| 返回上一层 | 180–260ms |
| 状态颜色过渡 | 120–200ms |

实际时长需要根据屏幕尺寸、交互距离和动画节奏进行调整。

### 8.3 递归菜单动效

**进入下一层：**

- 触发项先产生轻微激活反馈。
- 新菜单从父项附近派生。
- 旧层级根据布局模式保留或退出。
- 动画应让用户清楚感知“进入更深层级”。

**返回上一层：**

- 当前层向父级方向收回。
- 父级内容自然恢复。
- 返回方向应与进入方向形成空间逻辑上的对应。
- 不允许突然跳转或闪现。

**原位替换模式：**

- 通过交叉淡入淡出、短距离位移和受控高度变化实现切换。
- 动画前后保持整体锚点稳定。
- 尽量避免因为菜单高度变化导致整个组件突然移动。

### 8.4 动画中断与连续操作

必须支持：

- 展开过程中立即关闭。
- 关闭过程中再次展开。
- 连续进入不同子菜单。
- 快速返回多个层级。
- 菜单动效执行期间外部状态发生变化。

动画必须能够正确中断、反向或重新计算。

禁止出现：

- 动画叠加
- 状态失同步
- 菜单闪烁
- 图标卡在中间状态
- 动画完成后组件位置错误
- 已关闭菜单仍拦截点击事件

### 8.5 拖动动效

拖动行为必须强调直接操作感。

拖动过程中以实时跟手为最高优先级，不应使用过强的弹簧跟随造成明显滞后。

拖动结束后的视觉反馈可以采用轻微弹性恢复，但必须快速、稳定。

### 8.6 动效降级

尊重 `prefers-reduced-motion`。

当系统开启减少动态效果时：

- 移除大幅位移与弹性效果。
- 缩短或取消错峰动画。
- 保留必要的状态过渡。
- 不影响任何菜单功能。

---

## 九、微交互与状态反馈（Micro-interactions）

### 9.1 按钮微交互

为以下状态设计精细反馈：

- 悬停
- 按下
- 松开
- 选中
- 激活
- 加载
- 禁用
- 拖动
- 展开与收起

建议通过轻微缩放、描边变化、背景色过渡及阴影变化表达状态。

不要依赖大幅变形或夸张动画。

### 9.2 菜单项激活反馈

点击操作项后：

- 立即给出视觉响应。
- 根据操作类型切换选中状态。
- 具有子菜单的项进入明确的展开状态。
- 互斥选项之间应正确更新激活标识。
- 异步操作期间应具备可识别的加载状态。

### 9.3 图标交互

- 图标采用统一的线条风格。
- 优先使用简洁、清晰的 Outline Icon。
- 统一线条粗细、视觉尺寸和图形比例。
- 图标状态切换应平滑。
- 不同图标之间进行必要的光学居中处理。

### 9.4 触觉反馈

在设备与浏览器支持且用户允许的情况下，可以提供可选的轻触觉反馈。

适用场景：

- 菜单打开
- 进入下一层
- 重要状态切换
- 拖动进入磁吸区域

触觉反馈不应成为功能成立的必要条件，且不能频繁触发。

---

## 十、响应式设计（Responsive Design）

### 10.1 Mobile First

采用多端优先的布局与交互策略。

首先确保常见手机视口下：

- FAB 可自由拖动。
- 菜单能够完整展开。
- 胶囊标签清晰可读。
- 各操作项拥有足够触控面积。
- 多级菜单能够稳定导航。
- 返回与关闭操作明确。

随后扩展至平板和桌面。

### 10.2 不同尺寸适配

**手机：**

- 优先纵向菜单。
- 在深层递归或横向空间不足时使用原位替换。
- 保持标签与图标的紧凑、舒适比例。
- 严格处理安全区域。

**平板：**

- 允许更灵活的双向展开。
- 可在空间充足时并列显示多个菜单层级。
- 保持合理的菜单最大宽度，避免过度拉伸。

**桌面：**

- 支持鼠标悬停与键盘交互。
- 允许更丰富的相邻展开布局。
- 支持适当提高信息密度，但不能牺牲视觉留白。
- 保持与多端一致的设计语言。

### 10.3 文本自适应

对于较长的标签：

- 优先根据文本内容自然扩展。
- 设置合理的最大宽度。
- 必要时使用受控换行或省略。
- 保证完整名称可以通过无障碍标签获取。
- 不允许长文本将图标按钮挤出屏幕。

### 10.4 安全区域适配

需要正确处理：

- iPhone 刘海与灵动岛区域
- 底部 Home Indicator
- Android 手势导航区域
- 圆角屏幕
- 横竖屏切换
- 虚拟键盘弹出
- 浏览器顶部和底部动态工具栏

组件必须根据实际可视区域计算位置，而不是假定 `100vh` 始终代表真实可用高度。

---

## 十一、可访问性（Accessibility）

组件必须满足现代 Web 无障碍交互的基本要求。

### 11.1 语义与标签

- 使用原生按钮语义构建交互项。
- 为图标按钮提供明确的可访问名称。
- 为可展开子菜单的节点提供展开状态。
- 正确处理禁用、选中及加载状态。
- 根据交互模型合理使用 ARIA 属性。
- 避免没有必要的复杂 ARIA 角色。

### 11.2 键盘支持

至少支持：

- Tab / Shift + Tab：焦点移动
- Enter / Space：激活按钮
- Escape：关闭当前层级或菜单
- 明确的返回操作：回到上一层

如采用完整的 ARIA Menu 模式，还应实现与其角色一致的方向键导航和焦点管理；否则应优先采用原生按钮组语义。

### 11.3 焦点管理

进入子菜单后：

- 正确建立新层级的焦点顺序。
- 当前层级的不可见内容不得继续接收焦点。
- 返回时恢复到对应父级操作项。
- 整体关闭时恢复合理的焦点位置。

### 11.4 视觉可访问性

- 常规文字对比度应满足 WCAG 2.2 AA 适用要求。
- 必要图标及控件边界应具有足够对比度。
- 焦点状态必须清晰可见。
- 所有可交互目标应具备舒适的触控面积。
- 重要状态不能仅靠颜色区分。
- 所有功能必须在减少动画模式下正常工作。

---

## 十二、组件架构与工程实现

### 12.1 模块化设计

建议拆分为以下职责模块：

**FloatingActionButton**

负责：

- 主按钮视觉
- 主按钮状态
- 点击与按压反馈
- 主图标切换

**DraggableController**

负责：

- Pointer Events
- 拖动阈值
- 实时位置更新
- 边界约束
- 磁吸策略
- 位置记忆

**SpeedDialMenu**

负责：

- 一级菜单渲染
- 操作项排列
- 展开与收起
- 菜单动画

**RecursiveMenu**

负责：

- 树状数据递归
- 父子节点关系
- 子菜单渲染
- 多级导航
- 返回逻辑

**AdaptivePositioning**

负责：

- 实时视口测量
- 自动展开方向
- 边界碰撞检测
- 相邻展开与原位替换切换

**MotionController**

负责：

- 动效配置
- 动画生命周期
- 动画中断
- 减少动态效果适配

**MenuStateController**

负责：

- 当前展开状态
- 层级路径
- 当前激活项
- 异步加载状态
- 全局关闭与重置

模块划分可根据实际技术栈调整，但必须保持职责清晰。

### 12.2 数据驱动

菜单必须由数据配置驱动。

每个菜单节点应支持以下信息：

- 唯一 ID
- 显示名称
- 图标
- 节点类型
- 是否禁用
- 是否选中
- 子节点集合
- 点击事件
- 异步动作
- 权限条件
- 自定义样式标记
- 展开策略
- 执行后是否关闭菜单

菜单结构不能依赖手工编写固定的多层 HTML。

### 12.3 状态管理

建议使用明确的状态模型管理交互流程。

至少包括：

- `isOpen`
- `isDragging`
- `activePath`
- `activeItemId`
- `expandedLevels`
- `placement`
- `position`
- `loadingItemId`

这些字段只是建议的状态表达，实际实现需要避免重复存储可推导数据。

尤其应保证：

- 拖动与点击互斥。
- 返回与整体关闭逻辑独立。
- 递归菜单状态不会互相污染。
- 快速操作不会触发竞态问题。
- 外部属性更新与内部状态保持同步。

### 12.4 性能优化

以主流移动设备上的流畅动画体验为目标。

重点要求：

- 优先使用 `transform` 和 `opacity` 实现动画。
- 通过 `requestAnimationFrame` 管理高频位移更新。
- 避免拖动过程中进行不必要的全组件重新渲染。
- 合理使用 Pointer Capture。
- 根据拖动区域管理 `touch-action`，避免不必要地阻止正常页面滚动。
- 减少频繁读取布局属性导致的同步重排。
- 避免大面积实时模糊和高成本视觉滤镜。
- 正确处理事件监听器、动画实例及观察器的生命周期。
- 避免深层递归菜单产生无意义的隐藏节点渲染。

目标是在性能允许的设备上保持接近 60fps 的流畅表现，并在性能较弱的设备上优先保证交互正确与稳定。

### 12.5 可配置性

组件应提供清晰的 API，允许配置：

- 初始坐标
- 主按钮尺寸
- 菜单项尺寸
- 主题色
- 图标与标签
- 展开方向
- 自动布局策略
- 拖动开关
- 磁吸开关
- 位置记忆
- 动效强度
- 动效时长
- 多级菜单展开模式
- 点击外部关闭
- 执行动作后关闭
- 菜单树数据
- 展开、关闭、选中与拖动事件回调

默认配置应达到较高视觉完成度，不应要求业务方重新配置大量参数才能获得理想效果。

## 十三、交互优先级与边界行为

### 13.1 拖动与菜单展开冲突

当用户在菜单展开状态下拖动主 FAB 时：

- 默认先收起完整菜单树。
- 确认进入拖动状态后更新 FAB 坐标。
- 拖动结束时保持菜单关闭。
- 下次点击 FAB 时从根菜单重新展开。

整个过程不得产生残留菜单、坐标错乱或意外触发。

### 13.2 递归深度过大

当用户不断进入更深层级时：

- 组件保持统一的视觉表现。
- 优先保证可返回、可理解、可操作。
- 根据屏幕空间自动调整布局模式。
- 不允许因为层级过深产生无限横向扩张。

### 13.3 菜单内容动态变化

当菜单展开期间发生：

- 新增节点
- 删除节点
- 节点禁用
- 文案更新
- 子菜单异步加载
- 权限变化

组件需要正确重新计算当前层级与菜单位置。

如果当前路径中的节点被删除，应安全回退到最近有效父级或根菜单。

### 13.4 页面其他浮层

当页面存在：

- Dialog
- Drawer
- Popover
- Tooltip
- Toast
- 全屏遮罩

需要通过统一的层级策略处理浮层关系。

不能盲目设置极大的 `z-index`。

FAB 不应覆盖更高优先级的模态对话框或系统级交互界面。

### 13.5 页面滚动

- 页面滚动时 FAB 保持相对于视口的位置稳定。
- 不得出现明显抖动或偏移。
- 若菜单处于展开状态，应保持空间锚点正确。
- 若视口发生变化导致布局不足，应重新计算展开位置。

### 13.6 动画与高频输入

连续快速执行下列操作时必须保持稳定：

- 快速展开与关闭
- 快速进入子菜单
- 连续返回
- 动画过程中点击其他菜单项
- 拖动过程中松开并再次按下
- 屏幕旋转时菜单尚未完成动画

状态正确性必须高于装饰性动画效果。

---

## 十四、设计细节与质量约束

### 14.1 禁止出现的视觉问题

- 粗糙的默认浏览器按钮样式
- 明显不协调的圆角
- 边框粗细不一致
- 阴影过深或过于模糊
- 高饱和配色堆砌
- 图标线条风格混乱
- 标签与图标未对齐
- 不规则的菜单间距
- 文本压缩、溢出或截断失控
- 元素尺寸和视觉重量失衡
- 无意义的渐变与发光效果

### 14.2 禁止出现的交互问题

- 拖动时意外打开菜单
- 点击时发生位置跳动
- 展开后部分菜单不可见
- 子菜单覆盖关键操作项
- 深层菜单无法返回
- 菜单关闭后透明元素仍阻挡页面操作
- 连续点击导致状态错乱
- 设备旋转后按钮消失
- 标签与图标触发不一致的行为
- 动画完成后布局突然改变

### 14.3 视觉精修要求

所有核心视觉细节都需要经过实际页面环境中的精修。

包括：

- 图标光学居中
- 文字垂直对齐
- 胶囊圆角曲率
- 按钮与标签比例
- 边框颜色与透明度
- 激活态的视觉重量
- 菜单项间距
- 主按钮与菜单的空间关系
- 阴影模糊范围与透明度
- 动效开始、结束及中断时的视觉连续性

**不应将“功能可以运行”视为开发完成，视觉细节和实际操作体验均属于交付范围。**

## 十五、测试场景与验收标准

### 15.1 基础功能验收

- 主 FAB 可正常展开和关闭。
- 主 FAB 可在有效视口内自由拖动。
- 点击和拖动不会相互误触发。
- 位置可根据配置进行持久化。
- 页面刷新后可正确恢复位置。
- 每个菜单项可正常执行操作。
- 选中与激活状态能够正确显示。

### 15.2 多级菜单验收

- 一级菜单可正常进入二级菜单。
- 二级菜单可继续进入三级菜单。
- 更深层级使用同一递归机制处理。
- 返回上一层功能正确。
- 一键关闭整个菜单树功能正确。
- 关闭后再次打开默认回到根菜单。
- 父级节点与叶子节点行为明确。
- 动态菜单数据更新后状态保持一致。
- 深层菜单不会出现无效路径或不可返回状态。

### 15.3 响应式验收

至少覆盖：

- 320px 左右的窄屏视口
- 常见手机尺寸
- 大屏手机
- 平板
- 桌面浏览器
- 横屏
- 纵屏
- 浏览器缩放
- 虚拟键盘弹出

验证在不同场景下：

- FAB 始终可见。
- 菜单不发生不可接受的溢出。
- 子菜单可正确切换布局模式。
- 触控区域保持可操作。
- 标签、图标与边框保持视觉协调。

### 15.4 边界位置验收

需要分别将 FAB 放置在：

- 左上角附近
- 右上角附近
- 左下角附近
- 右下角附近
- 屏幕中央
- 左右边缘中部
- 顶部和底部中间区域

在每个位置测试：

- 一级展开
- 二级展开
- 三级展开
- 返回
- 整体关闭

所有场景均应具有正确的方向选择和边界处理。

### 15.5 动效验收

- 展开与收起具有自然的空间逻辑。
- 多级菜单进入与返回动效方向合理。
- 连续快速点击不会造成视觉闪烁。
- 拖动过程具有良好的跟手性。
- 动画不影响功能执行。
- 减少动态效果模式下功能完整。
- 在性能允许的设备上保持流畅的视觉表现。

### 15.6 可访问性验收

- 所有操作具有明确语义。
- 键盘能够完成主要菜单操作。
- 焦点在层级切换时正确转移。
- 关闭菜单后焦点恢复合理。
- 触控区域满足尺寸要求。
- 文本及必要图形具有足够对比度。

最终交付的不是一个简单的 FAB 按钮或只能展开一级菜单的基础 Speed Dial，而是一个 **完整、可复用、可配置、支持递归层级的高品质悬浮快捷操作系统**。

必须满足以下标准：

### 视觉层面

完整继承参考图片所体现的：

- 细描边圆形按钮
- 胶囊形文字标签
- 低饱和灰蓝与青绿色彩
- 轻柔的悬浮阴影
- 精确的几何比例
- 充足且有节奏的留白
- 简洁、有秩序的垂直布局

并在此基础上提升至高品质商业数字产品的细节完成度。

### 交互层面

实现：

- 任意位置自由拖动
- 点击与拖动手势区分
- 一级快捷菜单展开与收起
- 任意层级递归子菜单
- 返回上一层
- 一键关闭整个菜单树
- 菜单节点激活状态
- 智能方向选择
- 层级空间不足时自动切换展示策略

### 动效层面

实现：

- 主按钮图标自然切换
- 菜单依次展开
- 菜单平滑收起
- 子菜单递进式进入
- 返回时反向过渡
- 精细的按下反馈
- 拖动浮起与释放反馈
- 可中断、可恢复的动画状态

### 响应式层面

保证：

- 平板与桌面兼容
- 自适应菜单方向
- 自动视口边界约束
- 深层菜单布局自适应
- 安全区域适配
- 页面滚动与屏幕旋转时保持稳定

### 工程层面

保证：

- 树状菜单数据驱动

- 模块化组件结构

- 可用于实际生产环境

## 十七、核心设计原则与最终质量标准

整个系统必须坚持以下原则：

**1. 以参考图为视觉基准，而不是仅把它当作一个宽泛的设计灵感。**

圆形按钮、胶囊标签、细描边、柔和底色、低饱和强调色及轻量阴影是需要明确保留的核心特征。

**2. 以自由拖动为基础能力，而不是附加功能。**

菜单展开位置、递归布局及碰撞检测均必须围绕 FAB 的实时位置工作。

**3. 以递归菜单为原生架构，而不是通过多个独立弹窗模拟层级。**

所有层级应共享统一的数据模型、交互逻辑、动画系统和布局规则。

**4. 以智能混合布局适配实际使用场景。**

空间充足时呈现富有层次的递进式菜单；空间不足时平滑切换为原位导航，始终保持功能完整。

**5. 以视觉克制实现高级感。**

不依赖复杂渐变、大面积玻璃模糊、夸张发光或过度装饰。高级感应来自比例、留白、描边、色彩、对齐和动效细节。

**6. 以操作效率约束动效。**

所有动画必须具有明确目的，且不能阻碍用户连续操作。

**7. 以生产级品质作为验收标准。**

除了功能正常，还必须考虑响应式、无障碍、性能、边界场景、维护成本和长期扩展能力。

### 最终目标

打造一个融合 **Twitter / Tumblr 风格的 FAB 快捷交互、参考图片所体现的极简胶囊式视觉语言，以及支持无限层级数据结构的递归 Speed Dial 菜单系统**。

它应具备 Awwwards、Webby Awards、FWA 优秀数字体验作品所追求的设计精度、交互质感和整体完成度，同时保持成熟 Web 产品所需要的稳定性、可访问性与工程可维护性。

**最终效果必须是：视觉轻盈、布局严谨、拖动自由、展开自然、层级清晰、递归流畅、交互精准、响应稳定。**

所有设计与技术决策均服务于这一目标，不能为了增加形式上的复杂度而破坏参考图原本干净、克制、精致的视觉气质。
