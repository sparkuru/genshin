# 编排、忠实表达与原文溯源

## 先判断视频在做什么

通读选定时间轨，结合关键画面区分：讲知识、论证观点、演示操作、访谈问答、复现事件，或混合内容。报告结构服务于这些内容，不用单一模板抹平差异。

| 内容 | 优先保留 | 截图价值 |
|---|---|---|
| 课程、演讲 | 定义、推导、例子、适用条件 | 公式、图表、板书、结构图 |
| 操作演示 | 环境、操作顺序、参数、观察到的结果、失败条件 | 状态变化前后、关键输入输出、短暂弹窗 |
| 访谈 | 说话者、问题、回答中的限定与分歧 | 提供必要现场语境时有用；不机械地截人像 |
| 评论、观点 | 作者的主张、依据、推测、反例和不确定性 | 原图、数据出处、原文展示；装饰性画面价值较低 |
| 无声画面 | 实际可见的操作或事件、时间关系 | 需要加密检查关键变化；不从画面臆测未显示的对白或意图 |

可按主题重排，但不能把不同时间的条件与结论拼成新的因果链。省略重复、寒暄、推广可以记录为 omitted；重要反例、警告、失败步骤或不确定性不能因不方便归纳而删除。

## 字幕选择与差异处理

平台人工字幕、平台 AI、独立 ASR、OCR分别保留。来源清单中的 ai_type 等标记原样保留，不能仅因“来自平台”就称为人工字幕。检查人名、术语、数字、单位、否定词、程度词、条件词、代码/命令和说话者变化。内嵌图像字幕、画面烧录字幕需要查看/OCR，不能以没有文本轨为由跳过。

识别可用性与内容可靠性分别记录。例如 API 错误后使用 ASR：保留 observed_status=error，说明没有证实平台无字幕；平台轨 available 但错词多：状态仍为 available，说明改用 ASR 的理由。

对关键或可能有歧义的表述，不以“多数模型赞同”消除歧义。可结合原音、上下文、画面术语、作者展示的资料判断；仍不确定时并列候选，说明影响。不把凭语境补全的数字、日期或人名写成已确认原话。

## 最终报告中如何保留原文与处理结果

所有影响理解的修订写入 `evidence/editorial-review.json` 的 edits，并在报告中保留能看到原文和处理后内容的位置。可采用表格：

| 编号与位置 | 原始识别/原始画面文字 | 处理后内容 | 处理理由及不确定性 |
|---|---|---|---|
| E1 · P1 03:20 | 按来源逐字保留 | 整理后表述或并列候选 | 错词、断句、冲突或尚未听清；附来源链接 |

“原始识别”不是“已确认的原视频原话”。若经过听辨，应说明听辨区间和依据；原始机器记录仍不能被覆盖。引用跨多个字幕段时，按顺序列 segment_ids，原始文本必须可从对应轨道还原。纯删除口头重复通常可在编排说明里统一交代；影响否定、条件、数值或结论的修改应单独记录。

原视频已有错误或争议也要忠实呈现：“作者说 X；补充核查显示 Y”。外部资料用链接、访问时间和核查范围单列，不能让 Y 悄悄替换 X。数学、医学、法律、金融等需要额外核查时按当前任务和可用专业工具处理；未做全面核查须如实说明。

## 选图

先看联系表，再查看计划采用的每张原图。清晰度、信息量和对当前段落的解释作用优先。可用 `frame` 在更合适时刻重新截图，不以低质量粗采样图凑数量。不人为重绘或“修复”原图中的关键数字、图形、代码和字幕。若用户另需整理示意图，清楚标成派生图，保留原图并另说明来源；当前机械验证器默认处理原视频截图，扩展派生图支持需明确实现。

图注写实际 P 号与时刻，说明图中支持什么，不把背景素材当成数据证据。精确提取记录保存源视频与图片哈希；视频帧边界存在舍入，不宣称截图具有超出源帧率的时间精度。

Pandoc 默认会把独立图片的替代文字转换成图注。使用 `![图注](../assets/图片.jpg)` 时，不要再另写一段相同图注；检查导出结果，避免重复标题或重复图注。

## 联动其他 Skill

只有对当前材料有实际作用时才调用，先读对应 SKILL.md，再遵守其要求和当前授权。正文润色保留作者语气与限定；领域报告可以调整编排格式，但不能新增视频没有展示的操作、复现结果或数据。把调用名称、作用、来源和是否引入外部说明记入 skills。没有调用就保留空列表，不声称已联动。

## 最后审读

对照视频、选定轨道和覆盖记录，检查报告是否忠于作者的目的、是否漏掉结论的条件、是否混淆不同时点、是否把观点写成事实。通读正文，查看所有采用的截图、图注、关键溯源表和生成文档。程序通过只证明文件和记录之间的机械关系；它不会替 agent 判断信息是否有价值，也不会验证报告语义。
